# Evidence Export Contract V1

## Purpose

`GET /api/v1/action-requests/{request_id}/evidence` returns a portable, tenant-scoped record for one governed action. It is for a company’s internal audit, incident review, pilot evaluation, or downstream evidence store.

## Included evidence

- The action request, policy outcome, risk explanation, and typed business context.
- Approval identity, status, and timestamp when an approval was required.
- Provider-neutral execution receipt: evidence status, provider reference, digest, outcome, and recovery posture.
- Causally sequenced audit events generated by the governance workflow.

The export intentionally presents the validated `action_context` separately. The internal storage envelope is never exposed as a provider parameter.

Each action-scoped event carries a durable `sequence`. This is the causal order of the lifecycle, including when multiple events share the same database timestamp. See `AUDIT_SEQUENCE_RELIABILITY_V1.md`.

Each export also includes an `integrity` object containing a SHA-256 digest of
the stable evidence contents. `exported_at` and the integrity object itself are
excluded, so an unchanged action has the same digest across repeated exports.
This detects a changed portable JSON record; it is not a digital signature,
does not prove source-system data, and does not replace provider reconciliation.

## Security rules

- The request is tenant scoped by the same server-derived tenant boundary as all action reads.
- A missing or cross-tenant request returns `404`.
- The export is a read-only evidence record; it cannot approve, execute, recover, or change an action.
- An export does not prove a recovery occurred. It states the declared recovery posture and provider outcome only.

## Product use

The action case file includes **Download evidence JSON**. This is the first portable evidence artifact for design-partner pilots; a later release can add tenant-controlled signing keys, provider verification, and automated retention controls after the selected customer workflow is validated.
