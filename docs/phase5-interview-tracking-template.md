# AgentOS Phase 5A — Customer Interview Tracking Template & Ledger

**Version**: Phase 5A Tracking Protocol v1.0  
**Status**: ACTIVE TEMPLATE (To be updated as customer interviews occur)  

---

## 1. 18-Field Customer Interview Ledger Matrix

| Field # | Field Name | Description & Data Standard |
| :-: | :--- | :--- |
| **1** | **Customer** | Organization name / Anonymized identifier (e.g. Brex / CUST-01) |
| **2** | **Contact** | Name & Title of interviewee |
| **3** | **Persona** | Role category (CISO / CTO / Head of AI / Treasury Tech / SRE Lead) |
| **4** | **Wedge** | Candidate Market Wedge (Finance / IT-SRE / CustOps / SecIAM / DevEng) |
| **5** | **Interview Date** | Date & Time interview conducted |
| **6** | **Agent Actions** | Active or planned tool calls executed by AI agents in their stack |
| **7** | **Highest-Risk Action** | Single action causing greatest security or financial anxiety |
| **8** | **Current Control** | Authorization solution currently deployed (Prompts / Gateway / Code) |
| **9** | **Pain Severity** | Score (1 = Low, 5 = Severe) based on empirical operational impact |
| **10** | **Urgency** | Active Q3 priority vs exploratory long-term research |
| **11** | **Existing Workaround** | How they currently bypass or solve the authorization gap |
| **12** | **Budget Signal** | Identified budget, discretionary spend, or willing annual spend range ($/yr) |
| **13** | **Pilot Signal** | Commitment to run 30-day sandbox pilot (Yes / No / Conditional) |
| **14** | **Requested Capability** | Specific integration, protocol, or policy control requested |
| **15** | **Objections** | Primary security, architectural, or organizational reservations |
| **16** | **Evidence Strength** | Empirical evidence rating (1 = Weak, 5 = Very Strong) |
| **17** | **Follow-Up** | Agreed follow-up items or technical review date |
| **18** | **Next Action** | Specific next step for AgentOS lead (Priyank) |
