## 1. Evidence Collection Framework & Schema

To maintain empirical rigor, all evidence collected during discovery interviews is logged using the standardized schema below.

### Evidence Strength Rating Scale (1 to 5)
- **1 (Weak)**: Casual opinion or hypothetical statement (e.g. *"That sounds like a neat idea"*). No budget, no active initiative.
- **2 (Low-Moderate)**: Acknowledges problem exists, but low priority. Has informal workarounds in place.
- **3 (Moderate)**: Verified active problem with clear operational impact. Currently evaluating or building internal workarounds.
- **4 (Strong)**: Critical operational or security pain. Active initiative with executive sponsor and allocated budget.
- **5 (Very Strong / Pilot Ready)**: Urgent, severe pain. Demands immediate pilot, willing to pay, technical team ready to integrate within 14 days.

## 2. Customer Evidence Register Template

| Field Name | Description | Data Category |
| :--- | :--- | :---: |
| **Customer ID / Persona** | Anonymized identifier (e.g. CUST-01 / CISO at Mid-Market SaaS) | Observed Fact |
| **Industry & Size** | Business sector & total employee count | Observed Fact |
| **Agent Maturity Level** | Stage of AI agent adoption (Exploratory / Staging / Production) | Observed Fact |
| **Active / Planned Agent Actions** | Specific tool calls or API endpoints executed by AI agents | Observed Fact |
| **Direct Customer Problem** | Primary operational, security, or compliance pain point stated by customer | Customer Quote / Fact |
| **Exact Workflow** | Step-by-step business process where agent action occurs | Observed Fact |
| **Current Workaround / Tool** | Existing solution (e.g. system prompts, custom Python if/else, Portkey) | Observed Fact |
| **Why Current Solution Fails** | Exact failure mode of current workaround | Customer Quote / Fact |
| **Consequences of Failure** | Direct financial, security, or operational impact if agent acts maliciously | Customer Quote / Fact |
| **Desired Control Mechanism** | How the customer wants to enforce authorization and human review | Customer Opinion |
| **Willingness to Pilot** | Rating & commitment to run 30-day sandbox pilot | Customer Quote / Fact |
| **Willingness to Pay** | Budget allocation & estimated annual spend tolerance ($/mo or $/yr) | Customer Quote / Fact |
| **Requested Integration** | Specific API, protocol, or identity connector requested | Customer Quote |
| **Primary Customer Objection** | Main reservation or integration blocker raised | Customer Quote |
| **Evidence Strength (1–5)** | Overall evidence validity score based on empirical criteria | Our Inference |
